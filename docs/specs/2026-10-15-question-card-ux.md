# 选项卡交互优化：完整阅读、勾选反馈与可靠输入

- 日期：2026-10-15
- 类型：方案期 spec
- 状态：已实施（PR #9）
- Issue：#7
- 现状基线：`a90e8754c6540a625a041c5e3980088706e092bd`
- 适用环境：Pi 1.2.x 的终端交互模式（TUI）
- 用户确认：本轮选择「全要」，同意滚动阅读区、多行编辑器、可回看答题状态三项机制；后续回复「go」，进入规格定稿。

## 1. 目标

用户需要先完整阅读问题及选项，再清楚地勾选、输入补充并提交答案。目前长文本被省略，选中反馈不足，Other 无法接收整段粘贴。

本轮优化已有 `ask_user_question`，不新增另一个问答工具。交付后应满足：

1. 问题、选项标题、描述和预览均能读到全文，不因终端宽度而丢失内容；超屏内容可通过键盘阅读。
2. 光标焦点与已选状态明确区分，已选项有标记、文字颜色和加粗反馈。
3. Other 可粘贴、浏览和编辑多行内容，不仅能逐字输入。
4. 单选、多选、补充、返回修改和取消的语义一致，不误选、不静默提交空答案、不丢草稿。
5. 提交后能核对实际交给模型的答案，保持已有工具参数和结果结构兼容。

本文件定义需求、行为和验收，不编排实施任务或提交顺序。

规格工作区另已执行 `npm run check` 和 `npm test`：169 项现有测试全部通过。按仓库指令及约定路径检查，无文档检查入口；这不是文档检查绿灯。

## 3. 范围

### 包含

- 现有终端卡片的布局、换行、超屏阅读和主题反馈。
- 单题和最多 4 题的单选、多选与 Other 编辑。
- 各题独立草稿、选择、完成状态及返回修改。
- 空答案校验、单选互斥、多选补充、取消与中止清理。
- 本工具专用的答案回执及对应自动化测试、终端验收和 README 说明。

### 不包含

- 修改 Pi 核心或 fork Pi；新增第三方运行时依赖。
- 改造 monitor、subagent、task_stop，或更换所有工具的共用渲染行为。
- 新增鼠标交互作为必需操作、动画、图形界面或跨会话草稿保存。
- 更改题数、选项数、header 上限，或新增工具参数。
- 重写 RPC 客户端及其选择交互；RPC 保持当前降级行为，不能宣称获得终端勾选样式或全文阅读能力。
- 改写已合并的原工作流规格。本文件是仅针对选项卡的新规格。

## 4. 阅读与布局

### 4.1 信息层级

卡片依次呈现：简短题号和 header、完整问题、选项列表、当前选项的辅助预览、必要的操作与错误状态。选项标题与描述分行，描述续行保持一致缩进，不与勾选标记挤成一条长行。

- 问题、选项标题、描述、预览和最终答案不得通过省略号永久裁掉正文。
- 保留原文的显式换行；长 URL、无空格长词也必须换行。
- 按可见终端列宽而非 JavaScript 字符串长度布局；覆盖中文、宽字符、组合字符、emoji 和 ANSI 样式。
- 优先使用 Pi 的宽度和换行工具，不另写一套字符宽度算法。
- 宽度变化、当前题变化、预览变化和主题变化后，旧布局不得继续复用。

### 4.2 超屏阅读

仅增加换行不足以解决长文本：多行内容不能把题目推到屏幕外后就无法返回阅读。

- 正文放入高度受限的阅读区；题目全文也是可滚动正文的一部分，不固定成一个可能无限高的标题。
- 在常规与全屏 TUI 中都提供键盘翻页，顶部和底部均可到达；不能只依赖终端历史回滚或全屏专属滚轮。
- 题号、答题状态和必要操作入口在目标验收尺寸内可见；正文高度按终端行数及这些区域占用计算，不写死成若干正文行。
- 移动选项时自动让当前选项标题可见；遇到一个选项自身超过一屏时，用户仍可翻页读完描述。
- 翻页只改变阅读位置，不改变勾选；未移动选项时，普通重绘不得把用户刚翻到的正文强行拉回焦点。
- 预览仅跟随当前选项，进入同一阅读结构，不挤掉题目、后续选项或提交入口；无预览时不保留装饰性空面板。
- 终端缩放后重新换行并约束滚动位置，保持全部正文可达。

可以复用 Pi 的滚动与布局能力，但实施须验证它在常规、全屏和 `custom()` 挂载位置的实际行为；不能只把正文放进 `ScrollView` 就假定所有模式已经获得高度限制。

## 5. 勾选与主题

- 多选：未选 `[ ]`，已选 `[x]`。
- 单选：未选 `( )`，已选 `(*)`。
- 光标：独立箭头 `>`，不代表已选中；初始焦点可以停在第一项，但不能把它画成已选答案。
- 已选标记、标题及其描述使用主题的成功色，标题加粗；普通标题保持正文色，未选描述使用次级文字色。
- 焦点通过箭头和轻量主题强调区分；焦点移动到已选项时，不能覆盖其成功色或清除勾选。
- 同时存在多个已选项时，颜色和标记必须持续存在，不只高亮光标所在行。
- 使用 Pi 注入的主题语义颜色，不硬编码绿色 RGB；浅色、深色和终端颜色受限时都应可读。
- 颜色不是唯一提示；标记、箭头和字重仍能区分状态。

## 6. Other 编辑

### 6.1 输入与全文核对

Other 显示为「Other（自定义）」并保留系统提供该行的约定，模型不能自行重复添加它。

- 复用 Pi `Editor` 的输入和编辑能力，接收完整输入事件，不再按单字符过滤。
- 支持终端文本粘贴、带起止标记的粘贴、分块送达的粘贴，以及含换行、中文、emoji 的内容。
- 支持左右及上下移动光标、Backspace、Delete、行首行尾、换行和宿主已有的撤销等编辑动作。
- 宿主对长粘贴生成的标记必须还原成可浏览、可定位和可编辑的全文；不能要求用户提交后才知道到底粘了什么，也不能把标记文本交给模型当答案。
- 长输入采用受限高度及滚动，不把整张卡片无限撑高。
- 正确传播焦点并保留 Pi 的光标定位标记，让中文输入法候选窗口跟随真正输入位置。
- 粘贴中的换行属于正文，不能被逐个当成 Enter 自动提交。

### 6.2 草稿与答案分离

草稿是尚未明确采用的输入，不能因为存在草稿就自动成为答案。

- 进入 Other 时恢复本题草稿；第一次进入为空。
- 编辑态 Esc 回到选项列表并保留草稿，不取消整批问答，不自动采用尚未确认的文本。
- Enter 采用非空输入并确认当前题；空白输入显示错误，停留在编辑态。
- 选择其他题目、普通选项、取消 Other 的已选状态时，均不得意外删除可供再次编辑的草稿。
- 仅在本次卡片交互内保存；整批取消、工具中止或结束后释放，不写入跨会话记忆或外部文件。

### 6.3 选择语义

- 单选：普通选项和已采用的 Other 互斥；采用 Other 时清除普通项，选择普通项时不再提交 Other，但仍保留它的编辑草稿。
- 多选：Other 是可独立取消的补充项，允许与普通项同时采用；更改普通勾选不能清空已采用的补充。
- 多选已采用 Other 时，空格可取消它，Enter 可重新编辑；未采用时，空格或 Enter 进入编辑器。
- 多选中只有非空 Other、没有普通选项，仍是有效答案。
- 空格勾选仍不提交；多选 Enter 只确认已有选择，不能暗中把光标项加进去。

## 7. 多题回看与提交

每题分别保存已选项、Other 草稿、是否采用 Other、是否已确认，以及返回该题所需的焦点和阅读位置。编辑一题不能覆盖另一题。

- 保留单题快捷路径：普通单选 Enter 可直接提交；多选 Enter 确认已有选择；Other 非空确认可提交本题。
- 多题确认当前题后推进，但最后一题确认不直接结束工具：进入核对页，仍能返回任意题修改，最后再整体提交。
- 核对页呈现每题完整答案，内容过长时仍可滚动阅读；未答题清楚标出，不能因为越过了该题就当作完成。
- 题目间可前后切换。切换不等于确认，不清空草稿；返回时恢复状态。编辑态的文本移动按键优先留给编辑器。
- 每题必须有一个普通选择或已采用的非空 Other；空多选不能进入已完成状态。
- 整体提交前重新校验所有题，缺项时定位到对应题并显示错误；没有跳过必答题的隐式路径。
- 从列表或核对页 Esc 取消整批，返回 `cancelled`，不能把已有局部答案伪装成成功提交。
- 工具取消信号应使终端交互及时结束、释放焦点和活动卡片锁；重复取消不得重复结束交互，下一次调用仍可打开卡片。

按键继续采用 Pi 注入的配置。默认约定如下；正文内有编辑焦点时不得劫持编辑按键：

| 默认操作 | 行为 |
|---|---|
| 上下方向键 | 列表中移动焦点，不改变勾选；编辑器中移动文本光标。 |
| 空格 | 单选选中当前普通项；多选切换勾选；Other 按第 6.3 节处理。 |
| Enter | 确认当前题或采用输入；核对页提交整批。 |
| Tab / Shift+Tab | 非编辑态前后切换题目及核对页，不隐式确认。 |
| PageUp / PageDown | 阅读态翻页，不改变勾选；编辑态使用编辑器的翻页。 |
| Shift+Enter / Ctrl+J | 编辑态插入换行，遵循宿主配置与终端能力。 |
| Esc | 编辑态退回列表并保留草稿；列表或核对页取消整批。 |

同一终端不支持某种带修饰键的输入时，必须有表中可用的替代路径；不能把 Shift+Enter 当作所有终端都能区分的前提。

## 8. 答案契约与回执

### 8.1 不变的外部结构

沿用现有参数、数量上限和按 `id` 索引的结果：

```typescript
{
  kind: "answered",
  answers: Record<string, string>,
  responses?: Record<string, string>,
  annotations?: Record<string, Annotation>
}
```

- 普通单选返回一个选项 label，不因加了视觉标记而带上 `(*)`、勾选符号或颜色码。
- 多选继续按用户勾选顺序以 `", "` 连接；补充同时进入 `answers[id]` 和 `responses[id]`，后者只放 Other 正文。
- Other 保留内部换行及内容；边缘空白裁剪沿用现有规则，宿主已有的换行和制表符归一化不承诺逐字节保真。
- 保留 preview 的既有归属与结果规则，不把焦点预览正文混入答案。
- 核对页和终端样式不新增模型必须理解的状态或字段；草稿不进入结果。
- `cancelled`、`busy`、`ui_unavailable` 继续互相区分；JSON / print 不等待输入。
- RPC 保留当前单选、连续单选多选和 `degraded` 标记契约，不借本轮扩大 RPC 产品范围。

### 8.2 提交回执

终端结果不再只显示 `answered`：按每题显示其 header 或 id、已提交的选择与补充，并区分成功、取消、忙碌、无 UI 和参数错误。

回执以实际工具结果为准，不从当前光标重算答案。长内容自动换行；较长结果可使用 Pi 已有工具展开操作查看完整内容，不能由共用单行截断器永久裁掉。原始结构化结果仍完整交给模型，展示不得改写它。

只调整问答工具的结果渲染；其他三个工具的显示保持原样。

## 9. 验收标准

自动化测试和终端人工验收缺一不可。卡片组件测试须走真实输入处理、渲染和答案组装路径，不只测试独立 helper。

### 9.1 自动化

- [ ] 40、80、120 列下，长题目、标题、描述、预览和答案末尾均可通过渲染或翻页到达；每行可见宽度不超过可用列宽。
- [ ] 中文、emoji、组合字符、显式换行、无空格长 URL 和 ANSI 样式不产生丢字或宽度溢出。
- [ ] 正文超过视口时可到达头尾；移动焦点使标题可见，翻页不改变选择，重绘不重置手动阅读位置。
- [ ] 缩窄、放宽、降低终端高度和更换主题后，重新排版且状态不丢失。
- [ ] 单选、多选的未选、已选、焦点、已选且聚焦四类状态可区分；移动焦点不会改选；多选 Enter 不追加焦点项。
- [ ] 整段文本、多行中文、含 emoji、分块带标记粘贴，以及 1100 字符和 30 行长粘贴均可浏览、编辑并提交完整内容；结果不含粘贴占位标记。
- [ ] 粘贴内换行不触发提交；文本光标移动和删除按字素安全处理，不损坏 emoji 或组合字符。
- [ ] Other Esc 后再次进入恢复草稿；未采用草稿不进入答案；单选与 Other 互斥，多选补充不被普通勾选清空。
- [ ] 空白 Other、空多选和跳过的题不能成功提交；仅有非空 Other 的多选可以提交。
- [ ] 4 题前后切换、返回修改、核对页和整体提交均保存正确题目状态；结果仍使用原 id，答案顺序符合现有规则。
- [ ] 列表取消、编辑态退回、核对页取消、工具 AbortSignal、重复取消和下一次打开行为正确。
- [ ] 回执与工具结果一致，长答案可查看全文；RPC、JSON / print、并发 busy 和参数校验的既有测试继续通过。
- [ ] `npm run check`、`npm test` 通过，无新增第三方运行时依赖，无其他工具行为改动。

### 9.2 真实终端

## 11. 机制清单

|---|---|

## 12. 自定细节

以下是基于已确认目标作出的具体取舍，不是用户逐项指定的数值或按键：

1. 单选使用 `( ) / (*)`，多选使用 `[ ] / [x]`，焦点使用独立 `>`；采用 ASCII 标记以降低字体差异。
2. 勾选配色分两档：已选标题及描述使用注入主题的成功色、标题加粗；普通标题保持正文色，未选描述使用次级文字色。不硬编码某个绿色。
3. 问题全文进入阅读区，只有短进度等固定信息放在外侧；视口根据实际终端高度计算。
4. Other 的显示名为「Other（自定义）」，不改变既有保留 label 约定及结果结构。
5. 长粘贴还原为可编辑全文，不保留只能整体删除的占位标记作为最终编辑形态。
6. Other 的草稿与是否被采用分别保存；Esc 保留草稿，整批结束后清理，不持久化。
7. 每题必答，不提供隐式跳过；多选仅 Other 非空仍视为有效。
8. 单题保留快速提交；多题最后一题确认后进入核对页，再整体提交，以便完成最后一题后仍可回看修改。
9. 非编辑态 Tab / Shift+Tab 切题，阅读态 PageUp / PageDown 翻页；宿主可配置动作优先使用注入的按键管理器，编辑态不抢文本编辑按键。
10. 正文及结果采用完整换行；不要求新增 Markdown 表格排版能力、鼠标或视觉动画。
11. 自动化列宽选 40、80、120；真实终端尺寸选 40×12、80×24、120×40；长粘贴样例至少包括 1100 字符及 30 行。这些是验收样例，不是内容长度上限。
12. 本轮增强目标限定为终端交互模式，RPC 继续维持现状降级，不能承诺相同样式或交互。
13. 选项标题与描述分行，描述续行保持与标题同一缩进，不与勾选标记挤成一条长行。
14. 选择语义：单选普通项与已采用 Other 互斥——采用 Other 时清除普通项，选普通项时不再提交 Other 但仍保留其编辑草稿；多选 Other 是可独立取消的补充项，可与普通项并存，已采用时空格取消、Enter 重编辑。
15. 卡片以铺满终端的浮层方式挂载（宽 100%、高 100%、左下锚定）。这是全屏模式的硬约束而非审美取舍：Pi 全屏会先把 PageUp / PageDown 交给自己的对话区，挂在编辑槽里的普通组件收不到这套键（`TuiAltScreen.handleViewportInput` 只对聚焦中的浮层让路）。常规模式两种挂法都能收到，统一走浮层以免维护两套路径。附带的两个已知取舍：① 浮层让路覆盖整段视口键，卡片开着期间宿主自己的滚动键（PageUp / PageDown、Ctrl+Home / Ctrl+End）也归卡片，答题中回看转录需先取消卡片；② 卡片高度仍按编辑槽时代的算法留出 4 行，底部对齐、顶部露出 4 行宿主内容（不会裁切）。决定依据与实测记录见第 13 节。
