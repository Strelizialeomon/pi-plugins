# 选项卡对齐 Claude Code：布局、样式、交互与裁剪

- 日期：2026-10-15
- 类型：方案期 spec
- 状态：待审
- Issue：（待 spec 合并后开）
- 现状基线：`2f97930`（main）
- 适用环境：Pi 1.2.x 的终端交互模式（TUI）
- 前序规格：[`2026-10-15-question-card-ux.md`](./2026-10-15-question-card-ux.md)（已实施，本文件不改它）
- 用户确认：本轮用户选择「全抄」，并在四问卡上逐项确认：多题导航**抄 CC 的标签栏 + 末屏提交**（取消核对页）；长内容**抄 CC 的剪裁 + 标注**；新增机制**全要**（Notes 备注行 + Chat about this）；本轮规格**新开一份**，旧规格原样不动。

## 1. 目标

让 `ask_user_question` 的终端卡片在外观与交互上与 Claude Code 的 `AskUserQuestion` 卡片对齐，并借它的裁剪机制解决「文本一长卡片就撑满屏」。

交付后应满足：

1. 单选且带预览时使用左右并排布局；其余情况走单列列表。卡片高度不再随正文长度线性增长。
2. 全新视觉：字形（光标 / 勾选 / 多选框）、颜色语义（蓝紫=光标与当前题、绿=已选与已答、灰=描述与提示）、选项行结构、题目标签栏。
3. 全新交互：Enter 直接选中并前进、数字键直选、Tab 切题、`n` 加备注、Esc 取消。
4. 多题走「顶部标签栏 + 一屏一题 + 末屏整体提交」，核对页取消。
5. 超出上限的正文一律剪裁，并在框上标注剪掉了多少行；预览超过长度上限时整块不渲染，改为一句提示。
6. 新增备注与 Chat 两种能力，且不破坏既有答案契约（`id` 索引、`answers` / `responses` / `annotations` 结构）。

本文件定义需求、行为和验收，不编排实施任务或提交顺序。

## 4. 布局与尺寸

### 4.1 卡片骨架

卡片自上而下固定为：**标签栏 → 题目区 → 内容区 → 备注行 → 底栏提示**。标签栏与底栏恒在，内容区吃剩余高度。

- 内容区有两种形态：
  - **并排**：当且仅当本题是单选、且至少一个选项带 `preview`。左栏选项列表固定 **30 列**，右栏预览面板取剩余宽度；两栏间距 4 列。
  - **单列**：其余情况（多选、无预览）。选项列表独占内容区宽度。
- 左右并排时，内容区高度 = `max(左栏高度, 右栏高度)`，两栏各自封顶（见 4.3、4.4）；**不得**让右栏把左栏或底栏顶出屏幕。
- 单列时，内容区高度 = `min(列表高度, 上限)`，超出部分滚动（4.5）。

### 4.2 卡片高度上限

卡片整体（含标签栏与底栏）高度上限 = `终端行数 − 4`，沿用现状，给宿主留出底部 4 行。

任何会突破该上限的正文块——题目、选项描述、预览、备注——一律走第 6 节的剪裁机制，而不是把卡片撑高。**这是本轮对上一份规格「正文不得被永久裁掉」的正面取代**：上一版承诺全文可读、靠键盘翻页；本轮改为超限剪裁并在框上标注剪掉了多少行。

### 4.3 预览面板

- 宽度 = `终端列数 − 34`（30 列选项栏 + 4 列间距）；最小宽度 40 列，若终端宽度不足则该栏退化为整宽单列展示。
- 最大行数 = `max(1, 终端行数 − 卡片其他区块实际占用)`。其他区块占用按本卡实际渲染出的标签栏、题目区、备注行、底栏行数计算，**不照搬** 上游常量 26（那个数字编码的是它自己的 chrome 高度）。
- 内容先按面板内宽硬换行（不按字符串长度，按可见列宽），再按最大行数截断。
- 面板以边框包裹；被截断时，上边框替换为一段提示：`───── ✂ ───── N lines hidden ───`，`N` 为被剪掉的行数，整段以警告色渲染。
- 每一行按面板宽度截断，超宽处补省略号。
- 面板内无预览内容时（当前选项没有 `preview`）不渲染该栏，卡片退回单列，不留装饰性空面板。

### 4.4 选项列表

- 可见项上限 **5** 项；超过时列表滚动，并在底部给出位置提示（如 `3/6`）。
- 有描述时用竖排布局（标签一行、描述一行）；无描述时用紧凑单行。
- 选项数量上限仍为 4，加上固定的 Other 与 Chat 行后最多 6 行——只有 6 行时才触发滚动。

### 4.5 滚动

- 列表滚动只改变可见窗口，不改变焦点。
- 移动焦点时自动把焦点项滚进可见窗口。
- 终端尺寸变化后重新换行、重新计算上限；滚动位置不越界。

## 5. 样式

### 5.1 字形

按终端能力二选一；实现须在启动时判定一次并整卡一致。

| 用途 | Unicode | ASCII 回退 |
|---|---|---|
| 焦点光标 | `❯` | `>` |
| 已完成 / 已选勾 | `✔` | `√` |
| 多选已勾 / 未勾 | `☒` / `☐` | `[×]` / `[ ]` |
| 次级箭头 | `›` | `>` |
| 省略号 | `…` | `...` |

### 5.2 颜色语义

颜色取 Pi 注入的主题语义色，不硬编码 RGB。映射如下：

| 语义 | 用途 | Pi 主题槽 |
|---|---|---|
| 强调 | 焦点光标、当前题标签 | `accent` |
| 成功 | 已选标签、已答题标签与其勾、已选描述 | `success` |
| 次级 | 选项描述、Chat 行、回执行、标签栏非当前项 | `muted` |
| 极弱 | 底栏提示、序号、备注占位 | `dim` |
| 警告 | 剪裁标注 `✂ N lines hidden` | `warning` |
| 正文 | 问题、标签 | `text` |
| 错误 | 校验错误 | `error` |
| 边框 | 预览面板边框 / 剪裁标注所在边框 | `borderMuted` / `warning` |

规则：

- 颜色不是唯一提示——焦点有独立光标、已选有勾、已答有方框标记，去掉颜色仍可读。
- 焦点移到已选项上时，不得覆盖成功色或清掉勾。

### 5.3 选项行

- 单列形态：`❯ 1. 标签 ✔` —— 光标、序号、标签、勾四段；序号极弱色，标签在聚焦时为强调色、已选时为成功色并加粗，勾为成功色。
- 有描述时，描述另起一行，缩进与标签对齐，次级色；已选项的描述用成功色。
- Other 行：`❯ N. Other`，未填写时次级色；已有草稿时在标签后附 `· 草稿`。
- Chat 行：列表之后的独立一项，编号连续，文案 `Chat about this`。

### 5.4 题目标签栏

- 形如：`← ☒ 题一  ☐ 题二  ✔ Submit →`；当前题用强调色，已答题带已勾方框，未答带空方框；末屏的 Submit 项带勾。
- 宽度不足时按层降级：先按「当前题最多占可用宽一半、其余每项至少 6 列」压缩，再不足只显示 header，再不足显示 `Q1`…并截到 3 列。
- 单题卡片不渲染标签栏。

### 5.5 底栏提示

- 一行灰色提示，`·` 分隔：`Enter 选择 · ↑/↓ 导航 · Tab 切题 · n 备注 · Esc 取消`；键名一律按宿主键位配置渲染，不写死。
- 多题时导航段写 `Tab/↑↓ 导航`，单题只写 `↑↓ 导航`。
- 编辑 Other 时改为编辑态提示（确认 / 换行 / 返回），沿用现状。
- 备注行紧邻其上方：有内容时 `Notes: <内容>`，为空时灰斜体 `press n to add notes`。

## 6. 剪裁与长度上限

### 6.1 统一剪裁机制

题目全文、选项描述、预览、备注四类正文共用同一套：

1. 按可见列宽硬换行（中文、emoji、组合字符、无空格长 URL 都不得丢字或溢出）。
2. 超出该块行数上限的部分直接截断。
3. 在被剪块的边框上标注 `✂ ─── N lines hidden ───`，`N` 为剪掉的行数；无边框的块（如题目）在末尾单独一行给出同样标注。
4. 超宽行补省略号。

### 6.2 预览长度上限

- `preview` 原始长度超过 **2000 字符**时，整块不渲染，改为一行提示：`（预览过长，无法完整显示——请直接比较各选项的标签与描述）`。
- 该判定按字符数，与终端尺寸无关；被截下的内容不进入答案，也不进入结果。

### 6.3 与旧规格的关系

上一份规格的「问题、选项标题、描述、预览和最终答案不得通过省略号永久裁掉正文」与「超屏用键盘翻页」两条，自本规格起对 `ask_user_question` 失效，由本节取代。答案本身（用户提交的内容）仍然全文进入结果，只有展示层剪裁。

## 7. 交互与按键

### 7.1 选择语义

- **单选**：焦点停在某项上按 Enter = 选中该项并提交本题（不需要先按空格再确认）。数字键 `1..9` 直接选中第 n 项并提交。
- **多选**：空格切换当前项勾选；Enter 确认本题已有勾选，不把焦点项暗加进去；数字键切换第 n 项勾选。
- **失败即停留**：本题无任何有效选择时按 Enter/末屏提交，显示错误并停在原地，不静默通过。

### 7.2 Other

- Other 是列表最后一项，进入后为内嵌编辑器，复用现有的全文编辑器能力（粘贴、多行、emoji、光标移动）。
- 编辑态 Enter 采用非空输入并提交本题；空输入报错并停留。
- 编辑态 Esc 退回列表并保留草稿，不取消整批。
- 单选下 Other 与普通项互斥；多选下 Other 是可独立取消的补充项。
- 占位文案：单选 `Type something.`，多选 `Type something`。

### 7.3 备注

- 列表或备注行上按 `n` 进入备注编辑；备注属于当前题。
- 编辑态 Esc 退回并保留备注草稿；Enter 采用。
- 备注不参与「本题是否有效」的判定——只填备注不算作答。

### 7.4 Chat about this

- 仅单选、且非末屏提交态时提供；选中后不记录答案，整卡结束并返回 `chat` 结果。
- 已勾选/已填写的草稿在返回 `chat` 时一并丢弃，不写入结果。

### 7.5 按键总表

| 默认操作 | 行为 |
|---|---|
| `↑` / `↓` | 列表中移动焦点，不改变勾选 |
| `Enter` | 单选：选中并提交本题；多选：确认已有勾选；末屏：提交整批；编辑态：采用输入 |
| `1`–`9` | 直选对应序号项；多选为切换勾选 |
| `Space` | 多选切换勾选；单选等同 Enter |
| `Tab` / `Shift+Tab` | 前后切题（不隐式确认）；单题卡片不生效 |
| `←` / `→` | 与 Tab 等价，用于标签栏 |
| `n` | 编辑当前题备注 |
| `Esc` | 编辑态退回并保留草稿；列表或提交屏取消整批 |
| `Shift+Enter` / `Ctrl+J` | 编辑态插入换行，遵循宿主键位配置 |

所有键位一律读宿主注入的键位配置；宿主改绑后提示与行为同步。

## 8. 多题导航与提交

- 顶部标签栏呈现全部题目的 header 与答题状态，Tab / `←` `→` 横向切换。
- 一屏一题，取代上一版的「逐题确认后进核对页」：**核对页取消**。
- 末屏是提交屏（标签栏上的 `✔ Submit`）：逐题回看已提交的答案，缺项直接标出并定位到该题。
- 返回任意题修改后，已提交状态按该题的最新选择更新；不得出现「改完第一题、第二题答案丢失」。
- 每题独立保存：已选项、Other 草稿、备注草稿、是否完成、焦点位置。切换题目不串状态。
- 整批提交前重新校验所有题目；未答或未完成的题不能提交成功。

## 9. 结果契约与回执

### 9.1 新增字段

沿用现有结构，只做增量：

```typescript
{
  kind: "answered" | "chat" | "cancelled" | "busy" | "ui_unavailable" | "invalid_arguments",
  answers: Record<string, string>,
  responses?: Record<string, string>,
  annotations?: Record<string, { degraded?: boolean; notes?: string }>
}
```

- `notes`：本题备注，按 `id` 索引挂在 `annotations` 下；不进入 `answers`。
- `kind: "chat"`：用户选择先讨论而非作答。此时候选答案与草稿全部丢弃，`answers` 为空。
- 单选答案仍是一个 label；多选仍按勾选顺序以 `", "` 连接；Other 正文仍同时进入 `answers[id]` 与 `responses[id]`。
- 展示层新增的字形、颜色、剪裁标注一律不得进入结果。

### 9.2 回执

提交后转录里的回执改为上游式的一行条：

- 头行 `已回答 N 题`（成功色）。
- 每题一行：`· <header 或 id> → <答案>`，次级色。
- 答案过长时按终端宽度截断到一行并加省略号；完整内容仍在结构化结果里交给模型。
- `chat` 的回执写明「用户选择先讨论，未作答」；`cancelled` / `busy` / `ui_unavailable` 维持现有文案。

## 12. 机制清单

以下机制均为本轮新增（用户已在机制卡上选「全要」）：

| 机制 | 解决什么 / 没有它会怎样 |
|---|---|
| 并排布局与分栏高度 | 让预览不再把题目和选项往下推；没有它，长预览必然把卡片撑满。 |
| 统一剪裁 + `✂ N lines hidden` 标注 | 给超长正文一个确定的上界，并让用户知道被剪了多少；没有它，只能靠无限滚动，卡片高度不可预期。 |
| 预览长度上限（2000 字符） | 挡住不可能读的巨块预览；没有它，剪裁标注也只是把 5000 行剪成 20 行，用户仍然读不到该读的东西。 |
| 题目标签栏 + 末屏提交 | 一屏一题且随时可横向回看；没有它，多题只能线性前进或退回核对页。 |
| 备注（`annotations[id].notes`） | 让用户在不改变答案的前提下补充说明；没有它，只能把备注塞进 Other，污染答案。 |
| Chat about this（`kind:"chat"`） | 给出「不选，先聊」的合法出口；没有它，用户只能在选项里将就或整批取消。 |
| 字形与颜色语义表 | 让状态在无颜色、窄字体、ASCII 终端下仍可区分；没有它，样式只能硬编码。 |

## 13. 自定细节

以下是基于已确认目标作出的具体取舍，不是用户逐项指定的数值：

1. 预览栏行数上限按本卡实际 chrome 计算，不照搬上游常量 26；等价形式是「终端行数 − 标签栏 − 题目区 − 备注行 − 底栏 − 边框」。
2. 把上游只用于预览的剪裁机制**推广到题目、选项描述、备注**四类正文，理由是自己的卡片高度上限必须对所有区块成立。
3. 字形的能力判定：默认 Unicode；当 `TERM=dumb`，或 `LC_ALL` / `LC_CTYPE` / `LANG` 既不含 `UTF-8` 也不含 `utf8` 时退回 ASCII。
4. 颜色映射到 Pi 主题槽：强调=`accent`、成功=`success`、次级=`muted`、极弱=`dim`、警告=`warning`，不引入新的主题槽。
5. 备注落点 `annotations[id].notes`；Chat 走新增的 `kind:"chat"`，不占用 `responses`。
6. 数字键范围 `1`–`9`，编号连续覆盖普通项、Other、Chat；末屏无数字直选。
7. 列表可见项上限取 5，与上游一致；本工具选项上限 4，加 Other 与 Chat 才可能触发滚动。
8. 回执中过长的答案**截断到一行加省略号**（上游是整段换行）。理由：转录长期保留，一行一条更好扫；完整答案仍在结构化结果里。
9. 剪裁标注在无边框区块（题目、备注）改为紧跟该块末尾的独立一行，不引入新边框。
10. 标签栏降级阈值：当前题最多占可用宽一半、其余每项至少 6 列、最终回退 `Q{n}` 截到 3 列，与上游一致。
11. 预览长度上限 2000 **字符**（按 JS 字符串长度），与终端尺寸无关。
12. 单题卡片不渲染标签栏，也不提供 Chat（Chat 只在单选且宿主可继续对话时出现）。
13. RPC / `json` / `print` 维持现状降级，不获得标签栏、备注、剪裁样式；`kind:"chat"` 与 `notes` 在这些模式下不产生。
14. 多选列表的确认文案沿用宿主语汇（末屏「提交」、非末屏「下一题」），不照抄英文 `Submit` / `Next`。
